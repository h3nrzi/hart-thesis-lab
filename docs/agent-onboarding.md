# راه‌اندازی Codex و Antigravity روی یک مخزن مشترک

## نصب و اولین اجرا
۱. پروژه `https://github.com/h3nrzi/hart-thesis-lab` را Clone و همان پوشه را به‌عنوان Workspace باز کن.
۲. Codex و Antigravity از `AGENTS.md` مشترک استفاده می‌کنند. Antigravity فایل کوتاه `GEMINI.md` را هم می‌بیند؛ این فایل فقط به مرجع اصلی ارجاع می‌دهد.
۳. مهارت‌ها در `.agents/skills/*/SKILL.md` ذخیره می‌شوند؛ نیازی به کپی‌کردن دستورها در تنظیمات شخصی هر دستگاه نیست.
۴. به ایجنت بگو ابتدا `python3 -B scripts/check_worktree.py`، `python3 -B scripts/agent_status.py` و `python3 -B scripts/validate_structure.py` اجرا کند. فایل‌های ignored در `.gitignore` مانع نیستند و نباید پاک شوند.

## متن پیشنهادی شروع سشن
> این ریپو را طبق AGENTS.md بخوان. از آخرین Git HEAD و scripts/agent_status.py وضعیت را محاسبه کن. بدون نوشتن فایل و بدون خواندن محتوای TradingView، تعداد پرونده‌ها، مرحله و سؤال بعدی را فارسی اعلام کن. منتظر لینک یا محتوای ارسالی من بمان.

## متن کاربر در مراحل بعد
- **لینک:** «پرونده خام این لینک را طبق case-intake بساز: <link>».
- **متن اولیه:** «این متنِ استخراج‌شده توسط من برای شناسه <id> است؛ آن را با دستور ثبت نسخه اولیه ذخیره کن: ...».
- **آپدیت:** «این آپدیت استخراج‌شده مدرس برای <id> است؛ با لینک منبع و زمان در یک update جدید ثبت کن: ...».
- **نقد:** «با skillهای technical-reading و evidence-audit سندهای موجود را نقد کن و در review جدید ثبت کن».
- **نتیجه:** «مدرس در این آپدیت مشخص، پایان سناریو را بررسی کرده؛ فقط اگر شواهد کافی است، پیش‌نویس نتیجه را بساز».

## جلوگیری از هم‌پوشانی دو ایجنت
هر عملیات مستقل در شاخه متفاوت، مثلاً `agent/TEST1234/original-codex` یا `agent/TEST1234/update-antigravity` انجام شود. **هرگز دو ایجنت نباید هم‌زمان مستقیم روی main بنویسند.** قبل از ادغام PR تازه‌بودن مبنا بررسی شود.

## اقدام یک‌باره مالک مخزن در GitHub
برای الزام فنیِ PR و تست‌ها (کاری که این مخزن به‌تنهایی نمی‌تواند از طریق فایل ایجاد کند)، در تنظیمات GitHub برای شاخه `main` یک Ruleset یا Branch Protection فعال کن:
- هر تغییر به `main` از Pull Request عبور کند؛
- بررسی `validate` در GitHub Actions الزامی باشد؛
- Push اجباری و حذف شاخه محافظت‌شده ممنوع باشد؛
- ترجیحاً قبل از ادغام، شاخه با `main` همگام باشد.

این پیکربندی **هنوز توسط ما روی حساب GitHub فعال نشده** و نیازمند اقدام مجاز مالک است. بدون آن، قواعد در AGENTS/CI مؤثرند ولی راه دور زدن توسط نویسنده دارای دسترسی مستقیم باز می‌ماند.

## رفع تعارض
اگر `check_worktree.py` تغییر واقعی غیرignored گزارش داد، توقف کن؛ فایل کش پایتون را برای ادامه حذف نکن. اگر `agent_status.py` حالت `CONFLICT` برگرداند یا PR هنگام ادغام جلو نرفت، نوشتن پرونده متوقف شود؛ آخرین نسخه منبع خوانده شود، تفاوت با سند جدید به کاربر گزارش شود و سپس با مجوز مشخص ادامه پیدا کند.
